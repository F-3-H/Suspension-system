# 相空间可视化计算器

> 「汽车悬挂系统 · 综合可视化项目」的 **VIEW 04**。配色、排版与页面外壳遵循仓库的
> [`STYLE.md`](../../STYLE.md) 与 [`assets/theme.css`](../../assets/theme.css)；
> 本项目为离线自足，`styles.css` 里保留了一份与共享主题**同值**的 token 兜底（拷走整个目录也能双击运行），
> 两份是否同步由 `node ../../tools/verify-repo-style.cjs` 检查。
>
> 与其他三个视角共用同一套参数记法：**m 质量、c 阻尼、k 刚度、x 路面位移、y 车身位移**。

把"系统的状态"当成相空间里的一个点，把描述这个状态所需的属性当成坐标轴，
把微分方程当成挂在每个点上的箭头（向量场），把时间当成把点搬运出去的相流 ——
这个计算器就是这套思想的可操作版本。

**双击 `index.html` 即可运行**（纯静态、无构建、无网络依赖、无 CDN）。

---

## 一、它把哪些概念变成了可操作的东西

| 系统科学的说法 | 在这个界面里的具体形态 |
|---|---|
| 状态 = 一个点 | 图上那颗黄点；单击图任意位置即可把它放到那里 |
| 属性 = 坐标轴 | 方程左侧写几个变量，就有几个坐标轴 |
| 维度 = 属性的个数 | 写几行 `x' = …`，就是几维相空间（1 / 2 / 3 维自动切换） |
| 微分方程 = 向量场 | 满屏彩色箭头：方向＝下一刻往哪变，颜色＝变得多快（\|f\|） |
| 推演与回溯 | `▶ 正向演化` 与 `◀ 反向回溯`：同一个点沿时间向前/向后走 |
| 相流 | 拖出一个矩形，区域内每个状态都演化，看整片区域被拉伸、压缩、卷曲 |
| 系统结构（与某条轨迹无关） | 不动点及其类型、极限环周期、散度 ∇·f、最大 Lyapunov 指数 |
| 相体积是否守恒 | 实时的「散度 ∇·f」读数 + 相流面积比（刘维尔定理的具体形态） |

## 二、怎么用

- **单击图**：在该位置放置状态点（它随即带着这个状态演化）
- **拖出矩形**：框选一片状态区域 —— 里面每个点都是一条轨迹（相流），矩形会被相流拉变形
- **Shift+拖动**（或**中键拖动**）：平移视野 —— **一维、二维、三维都一样管用**
- **滚轮**：以光标为中心缩放 —— **一维相线也支持**
- **双击**（或左侧「重置视野」）：把视野放回预设范围
- **三维视图**：直接拖动旋转、滚轮缩放、单击在"与当前状态等深的平面"上放置状态；
  左侧「三维相流工具」可以框一团状态（半宽 + 每轴点数可调），看它被相流拉成什么形状
- **改方程**：左侧文本框里直接改，改完即重算维度、向量场与结构（不必点"应用"）
- **改参数**：滑杆一拖，向量场立刻跟着变（这就是"参数如何重塑系统"的直观形态）
- **深度分析**：求极限环周期与最大 Lyapunov 指数

### 方程按学生的写法写

```
# 以 # 开头是注释
g = 9.8                      # 不带 d/dt 的行 = 已知量（参数）
L = 1
dθ/dt = ω                    # 带 d…/dt 的行 = 微分方程；几个状态变量就是几维相空间
dω/dt = -(g/L)·sin(θ) - b·ω
```

- 四种等价写法都认：`dθ/dt`、`d θ/dt`、`d/dt θ`、`θ̇`（也兼容 `θ'`）
- 乘号写 `*` 或 `·` 都行；坐标名写 `theta` 也会在回显里显示成 `θ`
- **写方程的工具都在左栏**：分组符号盘（导数 / 希腊字母 / 函数 / 运算 / 随机外因），
  点一下就插到光标处；「整段模板」下拉给出 10 个能直接跑起来的方程组骨架
  （一维衰减、逻辑斯谛、双稳态、简谐振子、单摆、阻尼单摆、范德波尔、捕食—被捕食、
  随机路面悬挂、洛伦兹）——写方程最费劲的是开头那两行，所以给现成的
- 报错会指出**第几行第几列**，点那条错误就跳到编辑器里那一行；`Ctrl+Enter` 直接应用
- 左栏下方有**方程预览**：把刚写的方程排版成学生手写的样子（点号写法 + 自动判断的等价二阶形式）。
  它原来浮在相图左上角，把图挡住了 —— 现在挪进左栏，画布上只留一小块示意图
- 图左上角的**方程回显**用学生手写的点号写法（`ẋ`、`v̇`），并且**自动给出等价的二阶形式**：
  只要第一行恰好是 `ẋ = v`（v ≡ ẋ 是恒等式），力表达式里的 v 就会被换成 `ẋ`，于是
  ```
  ẋ = v
  v̇ = -w0² · (x - road(t)) - 2 · ζ · w0 · (v - roadV(t))
  ẍ = -w0² · (x - road(t)) - 2 · ζ · w0 · (ẋ - roadV(t))     ← 等价二阶形式
  ```
  这正是 `mÿ + cẏ + ky = cẋ + kx` 那种学生写的形式（单摆则显示 `θ̈ = -(g/L)·sin(θ)`）
- 点号是用 CSS 画在字母上方的，不依赖 Unicode 组合点——后者在部分字体里会飘位，
  而 v、θ、ω 这些字母根本没有预组合字符可用
- 可用函数：`sin cos tan asin acos atan sinh cosh tanh exp ln log sqrt abs sign floor ceil round min max atan2 pow hypot mod clamp step gauss sq`
- 可用常数：`pi π e tau phi`；`t` 是自变量（方程里用到 `t` 会被标注为**非自治系统**）
- 参数可以依赖参数（`L = g/9.8`），成环会被拒绝；`t` 不能当状态变量或参数名

### 悬挂系统（人系统的模型）：`mÿ + cẏ + ky = cẋ + kx`

- **y** = 悬挂系统顶部（车身）纵向位移 —— 状态变量
- **x** = 路面纵向位移 —— 随机过程，方程里写 `x(t)`（位移）与 `xV(t)`（速度）
- **m、c、k** = 车身质量 / 阻尼 / 刚度 —— **只有这三个可调参数**，没有 ω₀、ζ 这类中间量

界面里的骨架就是把这个方程解出 `ÿ`：
```
m = 240
c = 1200
k = 16000
dy/dt = v
dv/dt = -(k/m)*(y - x(t)) - (c/m)*(v - xV(t))
```
`v ≡ ẏ` 代进去就是 `mÿ = -k(y − x) − c(ẏ − ẋ)`，即 `mÿ + cẏ + ky = cẋ + kx`。
验收方式是**逐点检查残差** `R(t) = mÿ + cẏ + ky − cẋ − kx`：在 3001 个时刻上归一化残差 < 1e-9。

- 拖 **c**：阻尼越大响应越小（c ×4 → RMS 从 0.0697 降到 0.0429；c ×0.25 → 升到 0.1248）
- 拖 **k**：刚度 ×4 → 响应 RMS 明显改变
- 拖 **m**：位移 RMS 变化本来就弱（低频段响应 ≈ 路面位移，与 m 无关，这是物理），
  但**轨迹本身与加速度都明显不同** —— 断言盯的是这个


确定性相空间里"一个状态点只有一条轨迹"。外因一旦随机化，同一个点就对应**一族**轨迹，
能问的不再是"它去哪"，而是"**它在哪儿待得久**"。

**默认看到的仍然是路径**：载入含随机外因的方程时，界面停在「确定性」模式，
把路面固定成**一次实现**（种子可见、可换），于是相图上是**一条具体路径** —— 一个状态点在一条路面下怎么走。
只有主动点顶栏「随机外因」才会重复跑 N 次、给出概率云：

- 在方程里写上随机外因：`x(t)`/`road(t)`（路面位移）、`xV(t)`/`roadV(t)`（路面速度）、`xi(t)`（一般随机输入）
- 设激励谱（带限白噪声 / Kanai–Tajimi 路面谱 / 宽带白噪声）、强度 S₀、频带、谐波数
- 设**重复次数 N**、每次时长、随机种子，点「开始模拟」
- 结果：相平面上的**概率密度热图**（对数色标：颜色 = 每个状态点被访问的次数，越亮越常去）
  + 若干条**具体路径**（白线）+ **响应功率谱**（与输入谱并列，固有频率处标线）
- 面板里有「只画路径（不画概率云）」：只想要路径就勾上
- 同一个种子必然复算出一模一样的图（这是"随机模式能被验收"的前提）
- 底部两块子图（时间序列 / 功率谱）**并排**排列：随机模式一开就多一块面板，
  上下叠放会把纵向总高顶出去（人系统报障"功率谱密度框看不全"），所以拿宽度换高度
- 响应谱的口径：**对多次实现的周期图做集平均**、丢掉前 30% 的暂态、频格取到 ~2.5 rad/s。
  谱是**系统属性**，不该由某一次实现的抖动决定；频格太粗时 ω₀ 附近的峰会被量化到错的频点上
  （旧口径的频格宽 4.9 rad/s，界面上把 7.4 的峰读成了 4.909）

物理口径（也是验收口径）：激励用**谱表示法**合成 ——
`y(t) = Σ √(2·S(ω_k)·Δω)·cos(ω_k t + φ_k)`，于是"各频率占比"不是事后估计出来的，
而是**一开始就按 S(ω) 造进去的**，时间均方等于 `∫S(ω)dω`。
对悬挂系统而言，响应谱在 `ω₀` 附近鼓起的那一块就是"哪些频率占得多"；
1 自由度悬挂的响应位移方差可与 `∫|H(ω)|²S(ω)dω` 直接对账（本轮实测 0.5336 对 0.5341）。

> 迭代 3000 步 × 64 条谐波 × 100 次实现这种量级，**循环体里绝不能调三角函数**：
> 每条谐波维护一对 (cosθ, sinθ)，每步乘预先算好的旋转因子递推下去（误差 1e-13 量级）。


### 一个贯穿性的约定：时间位置属于使用者

任何**视图操作**（Shift+拖动平移、滚轮缩放、三维旋转、框选相流区域）都**不会**动时间游标，
也不打断播放 —— 你放到 t=9 看着相流变形，随手挪一下画面，它仍然停在 t=9。
调整**实现参数**（步长、积分方法、时长、方程里的参数）会重算轨迹，但会**把你所在的时刻搬过去**，
同样不打断播放。只有一种情况会回到 t=0：**初始状态真的换了一个**（在图上另点一个点、或拖初值滑杆）——
那是另一条轨迹的起点；而且此时若正在播放，会**从新起点继续播放**，于是可以一边放着一边点来点去比较不同初值。

### 方程写法（旧写法仍然兼容）

```
# theta' = omega 这种"代码写法"照样能编译，但推荐写成上面的 dθ/dt 形式
g = 9.8
L = 1
theta' = omega
omega' = -(g/L)*sin(theta) - b*omega
```

- 可用函数：`sin cos tan asin acos atan sinh cosh tanh exp ln log sqrt abs sign floor ceil round min max atan2 pow hypot mod clamp step gauss sq`
- 可用常数：`pi π e tau phi`
- `t` 是自变量（方程里用到 `t` 会被标注为**非自治系统**：向量场随时间变化，严格说相空间要多加一维）
- 参数可以依赖参数（`L = g/9.8`），成环会被拒绝
- `theta'`、`ω'`、`θ′`、全角字符都能识别
- 保留名：`t` 不能当状态变量或参数名（否则方程里的 `t` 会静默指向时间）；变量名不能与函数名相同

## 三、文件结构（五层，逐层可单独验证）

```
index.html                 装配页（经典 <script> 标签，因此 file:// 双击可用）
styles.css

src/core.js     第二层  数学内核：RK4/Euler/Heun、散度、雅可比、不动点、极限环、Lyapunov、
                        蒙特卡洛概率密度累加器、点云 PCA
src/random.js   第二层  随机外因：谱表示法合成（相位旋转递推）、PSD 估计（Welch）、可复现 PRNG
src/presets.js  第三层  14 个预设系统（一/二/三维各若干，附"这个系统看什么"的说明）
src/render.js   第四层  渲染：二维向量场/零倾线/轨迹/相流、一维相线、三维投影、时间序列
src/app.js      第五层  界面装配：状态机、方程编辑、参数滑杆、指针交互、读数面板
tests/verify-core.mjs        Node：数学内核的机械断言（63 项）
tests/verify-render.mjs      Node：渲染层的结构断言（50 项，用记录型画布）
tests/verify-app.mjs         Node：把真实 app.js 放进假 DOM 跑，断言"界面自己会重绘"+ 三个维度各自的交互 + "拖拽不重置画面"（61 项）
tests/browser-selftest.js    浏览器内自检（59 项，读真实像素、真实 DOM 与真实几何）
tools/serve.cjs              验收用的本地静态服务（会把浏览器请求记进 server.log）
tools/make-buggy-copy.cjs    反向对照一、二：把"帧循环断了"与"拖拽即重置"装回去，确认断言真会红
tools/layout-negative-control.cjs  反向对照三：把布局还原成"副图被挤出窗口"的版本
```

## 四、怎么验收（四层证据，各自独立）

```powershell
# 1) 数学内核：对解析已知答案
node tests/verify-core.mjs

# 2) 渲染层：记录型画布上的几何断言（不需要浏览器）
node tests/verify-render.mjs

# 3) 应用层：真实 app.js + 假 DOM + 假 rAF，只推进"帧"，看界面是否自己重绘、交互是否真的生效
node tests/verify-app.mjs

# 3b) 反向对照：确认第 3 层不是空转的断言 —— 三个都应当报出失败
node tools/make-buggy-copy.cjs
$env:PSX_APP="tools\app-buggy-copy.js"; node tests/verify-app.mjs; Remove-Item Env:\PSX_APP
node tools/make-buggy-cloud.cjs
$env:PSX_APP="tools\app-buggy-cloud.js"; node tests/verify-app.mjs; Remove-Item Env:\PSX_APP
node tools/layout-negative-control.cjs broken   # 然后刷新浏览器页面，看副图断言报错
node tools/layout-negative-control.cjs fixed    # 记得恢复

# 4) 浏览器内自检：真像素 + 真 DOM + 真几何
node tools/serve.cjs 4188 .
#   然后打开 http://127.0.0.1:4188/?selftest=1
#   页面会把结果打在屏幕上，同时回传到服务端 —— tools/server.log 里会出现一行 REPORT
#   布局类断言必须在**会触发问题的窗口尺寸**下跑。最省事的办法是让脚本把尺寸当参数逐个跑：
node tools/verify-sizes.cjs                        # 默认十个尺寸（1400×900 … 900×520）
node tools/verify-sizes.cjs 1024x560 1024x480      # 也可以只跑指定的几个
#   想看它"自己在动"：http://127.0.0.1:4188/?demo=1&preset=van-der-pol-2d
#   含随机外因的演示：http://127.0.0.1:4188/?demo=1&preset=suspension-random-2d
```

四层各自覆盖不同风险，缺一层就有一类错误测不到：

- 内核层能对上"解析解/文献值"（极限环周期 6.663、Lorenz 的 λ≈0.906、相面积 e^{-2at}），
  但完全测不出"画没画出来"；
- 渲染层能测出"箭头画到框外、方向反了、颜色与 |f| 脱钩、投影不可逆"，但测不出真实像素；
- 应用层能测出"帧循环断了、界面冻在第一帧、交互后不重绘、某个维度的缩放/平移根本没接上、
  **视图操作把时间冲回 0**、id 拼错、步长取成 NaN"—— **它测的是"界面自己会不会动"，因此它不许替应用渲染**；
- 浏览器层能测出"脚本没挂上、画布是空的、点击没落到正确坐标、副图被挤出窗口"，
  但它依赖浏览器能起来，而且**必须在会暴露问题的窗口尺寸下跑**。

- `file://` 双击打开：**已实测**（截图里地址栏是 `file:///E:/deepseek%20harness/…/index.html`）

### 十三次真实故障（都由人系统实测报障或验收断言发现）

**故障一：界面渲染出来了，但什么都不动**

**现象**：相图显示得好好的，但点击、拖动、滚轮、播放按钮全都"没反应"，时间读数永远停在 `t=0`。

**根因**：启动时的帧循环把职责拆成了两个人，而接力棒传丢了：

```js
requestAnimationFrame(function loop() { if (S.dirty) render(); tick(); });  // 只渲染一次
function tick() { stepPlayback(1); requestAnimationFrame(tick); }           // 只推进时间
```

第一帧由 `loop` 渲染一次，随后它调用 `tick()`，而 `tick` 排的是**它自己** ——
`if (S.dirty) render()` 从此再也不会执行：`markDirty()` 设的标志没有任何人读，
画面冻在第一帧，读数停在 `t=0`。不报错、不异常，只是永远不动。

**修法**：一个循环只留一个帧函数，重绘与推进在同一条链上（`frame()` = 该画就画 → 推进时间 → 排下一帧）。

**为什么之前的 37 项浏览器自检全绿却没发现它**：自检每一步之后都调用 `px.renderNow()` 替应用渲染了一次。
**自检自己把被测系统该做的事做了**，于是最关键的"界面会不会自己动"从来没被问过。
为此新增两道防线：`tests/verify-app.mjs`（只推进帧，绝不代劳）与
`tools/make-buggy-copy.cjs`（把故障装回去，确认断言真的会红——`renderCount 1 → 1` 当场复现）。

**故障二：一维相空间放不大、缩不小**

**根因**：屏幕↔世界的坐标换算只按二维写（`makeView` 会读 `bounds[1][0]`），而一维的 `bounds`
只有一段 `[[a,b]]` → **在事件处理器内部抛异常**。事件处理器里的异常是静默失效：页面不报错、
不崩溃、控制台之外毫无痕迹，用户看到的就是"滚轮没反应、点击没反应"。
**修法**：按维度分派换算（一维走自己的相线换算、三维走反投影），并顺手扫掉 `onPointerUp` 里
一处改名没跟上的旧函数引用（由应用层断言当场抓出）。

**故障三：图像下面那个时间序列坐标图看不见**

**根因**：不是渲染问题，是**布局溢出被 `body{overflow:hidden}` 裁掉**：
顶栏 62 + 播放条 ~70 + 相图 min-height 240 + 副图固定 168 + 说明条 28 = 568，
超过笔记本高度下的可视区（实测 innerHeight 只有 390），副图被推到窗口之外 ——
**画布尺寸正常、内容也画了，只是整体看不见**，所以任何"画布有没有内容"的断言都会通过。
**修法**：①flex 子项加 `min-height: 0`（canvas 的自动最小尺寸取自它的 `height` 属性，
会把容器撑住不让缩，这是关键一环）；②相图 min-height 降到 150，副图改用 `clamp(104px, 20vh, 176px)`；
③矮窗口媒体查询让说明条与副图标题先让位。

**故障四：拖拽之后可视画面被重置**

**现象（报障原话）**："在拖拽后可视画面不会进行重置"（希望如此）。

**根因**：`onPointerUp` 末尾有一句**无条件**的 `resetPlayback()`：

```js
} else if (d.mode === 'region') { ... }
resetPlayback();      // ← 平移、旋转、框选一松手，时间就回 t=0
markDirty();
```

于是"我只是想挪一下画面"也把时间冲回了 `t=0`，已经演化出来的轨迹与相流整个作废
（连同播放状态一起被清掉）。同类问题还波及：拖参数滑杆、换步长、换积分方法 ——
它们都会重算轨迹，但顺手把使用者的位置也清了。

**修法**：立一条约定——**时间位置属于使用者，不属于实现**。
视图操作（平移/缩放/旋转/框选）一律不碰时间、不打断播放；
重算类操作（改参数、换步长/方法/时长）用 `keepTime()` 把使用者所在的**时刻**搬过去；
只有"初始状态真的换了"（另点一个点、拖初值滑杆）才回到 `t=0`，且此时保留播放状态——
于是可以一边放着一边点来点去比较不同初值。

**反向对照**：把 `resetPlayback()` 装回去后，断言如实报错——
暂停下平移 `curF 3 → 0`、播放中平移 `curF 249 → 0 playing=null`、三维旋转 `curF 399 → 0`，
共 10 项变红。这也是"用实测值而不是用感觉"判定的地方：修复前时间会**回退**，修复后只会**向前**。

### 六次真实故障（都由人系统实测报障或验收断言发现）

**故障五：随机模式的概率密度图几乎是空的、标准差是 NaN**

**根因**：`S.mc` 配置对象里漏了 `dt` 字段，而它被三处使用（积分步长、随机信号采样间隔、频谱分辨率）。
`dt = undefined` 一路静默传播成 NaN，又被积分器里的**发散保护**（`isFinite(next) ? next : cur`）
替换成"沿用上一步的值" —— 于是轨迹变成一条**一动不动**的直线：24 次实现只得到 24 个采样点。
界面上不报错、不崩，只是"图看着奇怪"。定位靠的是把配置本身打进断言：
`count=24 outside=0 … dt=undefined`。

**教训**：防御性兜底能拦住**偶发的数值意外**，拦不住**恒定的配置缺失**；
兜底每触发一步都该计数，触发比例过高就要如实报错，而不是安静地沿用旧值。

**故障六：功率谱的归一化与频率轴都写错了，而它只表现为"图长得不对"**

**根因**：①归一化写成 `2|X_k|²/(dt·Σw²)`，少了 `1/dt²` 的量级（实测谱值大 4 万倍）；
②频率轴写成 `k/(N·dt)`（那是 Hz），却当 rad/s 用，取样点全落在信号带宽之外。
两处都不报错、曲线也画得出来。抓出它们靠**三把解析尺子**：单频信号验归一化
（`∫S dω = A²/2`）、过程实现验合成口径（时间均方 = 谱积分）、有解析峰的系统验频率轴
（悬挂响应峰落在 `ω₀·√(√(1+8ζ²)-1)/(2ζ)` 附近）。

**教训**：**要显示给人的频域量，必须先与一个解析可算的信号对账**；
没有解析对账场景的频域量，就不要显示——它的错误形态是"图看起来怪"，肉眼分不出
"物理如此"与"我写错了"。

**故障七：方程框里"看不到微分方程"**

**根因**：方程框固定 234px 宽，而回显用的是 `display:flex` + 不换行的分数排版；
悬挂方程那行有 50 多个字符，横向溢出到框外、被挤到视野之外。
人系统还给了参考图（`mÿ + cẏ + ky = cẋ + kx`），指出该用**点号写法**。

**改法**：改用点号（`ẋ`、`v̇`）—— 一行短得多；点号用 CSS 画在字母上方（不依赖 Unicode 组合点，
后者在部分字体里会飘位，v/θ/ω 也没有预组合字符）；框加宽到 300px（可 ⤢ 放大到 460px）、
允许换行、长行自动缩小一号字；并**自动补出等价的二阶形式**（第一行恰好是 `ẋ = v` 时，
把力表达式里的 v 按 v ≡ ẋ 换成 `ẋ`，显示为 `ẍ = …`）。

**故障八：随机模式下"功率谱密度框看不全"，且峰值频率读数明显偏低**

**根因（两个）**：
①随机模式多出一块 96–160px 的面板，与时间序列上下叠放后纵向总高超出窗口，底部再次被裁
（和故障三同一类）；控制条在窄窗口下还会换行成 3–4 行，把中间挤得更小。
②响应谱用的是**单次实现、不丢暂态、频格 4.9 rad/s** 的估计：`segments=6` 触发了 nperseg 下限 128，
于是 ω₀=8.165 附近的峰只能被报成 4.9 或 9.8，界面上读成了 **4.909 rad/s**。

**改法**：两块子图**并排**（拿宽度换高度）；子图行设为不参与压缩（`flex: 0 0 auto`），
让相图区去让位；`#center` 改为可滚动（宁可给滚动条，也不静默裁掉）；
三栏宽度改 `clamp()`，1024px 宽的屏上不再把右栏挤出屏幕；
响应谱改成**集平均 + 丢前 30% 暂态 + 频格 ~2.5 rad/s** → 读数回到 **7.363 rad/s**（理论 7.57）。

**故障九：把"方程回显"做在了相图上的浮层里，挡住了图；以及 HTML 里的 `\uXXXX` 不是转义**

**根因（两个）**：
①我把上一轮"方程要写成学生写法"的改进**做在了浮在相图左上角的那个框上**，而人系统要改进的是
**左边那个写方程的框**；浮层本身越大越挡图。②符号盘按钮写成
`<button data-ins="\u03B8">` —— **HTML 里没有 `\uXXXX` 转义**，属性值就是六个普通字符
`\u03B8`，于是点"θ"插进编辑器的是这串乱码、方程立刻编译失败。这个坏按钮从加上工具条那一轮
起就在界面上，一直没被发现，因为**以前的断言只读方程回显、从来没点过这些按钮**。

**改法**：方程回显搬进左栏（作为「方程预览」，不再浮在图上），画布上只留一小块示意图；
符号盘重做成 6 组（导数 / 希腊字母 / 函数 / 运算 / 随机外因 / 整段模板），
属性值改为真字符；新增模板下拉、错误行点击跳转、`Ctrl+Enter` 应用；
浏览器自检里逐个点按钮并断言编辑器里出现的是**真字符**（`indexOf('\\u') < 0`）。
另外顺手修掉一个同类的：二维视图里一直挂着「三维相流工具」面板。

**故障十：悬挂方程"不对"——多了 ω₀/ζ 两个莫名其妙的参数；而且拖 m/c/k 相图根本不动**

**根因（三个，一个比一个深）**：
①**符号不合**：方程用 `x` 表示车身位移、`road(t)` 表示路面，而人系统的记法是 `y` 是车身、`x` 是路面
（他给的式子就是 `mÿ + cẏ + ky = cẋ + kx`）。看着就不是他的方程。
②**多出中间量**：我写成 `w0 = sqrt(k/m)`、`zeta = c/(2*sqrt(k*m))`，于是参数表里冒出两个他不认识的量，
而且**它们还各自带着滑杆** —— 拖它既没有物理意义，又掩盖了真问题。
③**真 bug：派生参数被永久冻在默认值上**。`makeSystem` 的规则是"外部给了值就用外部值"，
而界面会给**每一个**参数都塞一个值（取自编译时算出的 `paramDefaults`），于是 `w0` 永远是默认那一版。
拖 k、m 滑杆时方程其实一点没变 —— 界面不报错、不崩，只是"相图不动"。

**改法**：`expr.js` 里区分**独立参数**（RHS 是数值）与**派生参数**（RHS 引用了别的参数），
派生参数在 `makeSystem` 时**按拓扑序用当前依赖值重算**，并忽略外部赋值；
界面只给独立参数装滑杆，派生量以**读数**形式给出、跟着基础参数联动；
悬挂预设与模板按人系统的符号重写，参数只有 m、c、k；
新增 `x(t)`/`xV(t)` 作为路面位移/速度的别名（*），并顺手拒绝了"参数依赖状态变量"这种写法。

验收用**残差**而不是"看着像"：`R(t) = mÿ + cẏ + ky − cẋ − kx` 在 3001 个时刻上归一化 < 1e-9，
即骨架与他的方程逐点等价；再断言拖 c/k/m 时响应与轨迹确实在变。

（* 别名的三条规矩都有断言：裸写可用、用户自定义优先、`x(t)` 调用形式不被抢占。）

**故障十一：一进来就被丢进"随机外因"模式，看到的是一片概率云，而他要看的是路径**

**根因**：载入含随机外因的预设时我做了 `setMode('random')`；而确定性模式下 `makeSystem` 没接外部输入，
路面恒为 0，轨迹会一路收敛到原点（画出来是"有问题的直线"）——两害相权，我当初选了自动切模式，
结果把人系统要看的路径藏起来了。

**改法**：确定性模式下把随机外因**固定成一次实现**（种子可见可换），于是默认画的是**一条具体路径**；
概率云只在主动切到「随机外因」时出现，并新增「只画路径」勾选框与"颜色 = 访问次数"的说明。

**故障十二：勾了「只画路径」，一拖动画面概率云反而冒出来；而且这个云拖不动**

**根因（一处代码的两个后果）**：
```js
if (img && !S.mc.pathsOnly) { 铺概率图 } else { 逐格画的退路 }
```
那个 `else` 本意是"没有离屏画布时的退路"，可**勾上「只画路径」时条件也为假** ——
于是掉进退路，把整张概率云**逐格画了出来**（实测 5954 个格子）。
而退路里把格子按**当前视窗**铺（`view.bounds`），于是云被拉伸着钉在屏幕上：
拖动时路径在动、云不动 —— 正是人系统描述的两个现象。

**改法**：`pathsOnly` 要**同时**跳过"铺图"与"逐格退路"；
两条路都把云锚在**统计时那个视窗**（`S.mc.runBounds`）上，并在图上用黄色虚线框把它标出来 ——
于是拖动画面时，云与那个框一起跟着相空间走，人一眼就知道"这块统计覆盖哪里"。

**验证**：`tools/make-buggy-cloud.cjs` 把故障原样装回去 → **2 项断言报错**
（`格子数=5954`、`平移前 x=56，平移后 x=56`）；修好后 121 / 121。
这里还有一条自身的教训：我第一版断言只查了 `drawImage` 调用次数（= 0 就通过），
而故障恰恰是从**另一条代码路径**（逐格画）冒出来的 —— **断言只覆盖"正常路径"，就抓不住"退路"**；
第二版把阈值式断言（`< 40` 个格子）改成"整屏底色之外一个格子都不许有"，因为悬挂的概率云只占几十格，
阈值太宽同样会让退路蒙混过关。

**故障十三：功率谱密度框"依旧看不全"——布局缺陷与窗口尺寸强相关，而我每次只在一个尺寸下验过**

**根因（两个）**：
①**在矮窗口下真的被裁**：实测 1024×500 时两块子图的底边在 416px，而窗口只有 407px ——
`#bottomPlots` 当时是 `flex: 0 0 auto`（不参与压缩），于是它连同操作条一起把中栏顶出窗口，
中栏虽然可以滚，但**不滚的部分看上去就是"看不全"**。
②**在能放下的尺寸下太挤**：功率谱画布只有 ~100px 高，而绘图区固定留了 48px 左内边距与 24px 下内边距，
曲线只剩 60px；画布底部还压着"输入谱 / 响应 S(ω)"两个与标题重复的图例，看着就像被裁掉。

**改法**：子图行改成"可压缩但有下限"（`flex: 0 1 auto; min-height: 84px`），相图下限降到 90px；
矮窗口下操作条改成**一行 + 横向滚动**（它是最能压缩的一块，3–4 行要吃掉 120px 以上），
并撤掉说明条与子图标题；功率谱的内边距随画布高度自适应（矮时 40/8/12/14），
画布内那两个与标题重复的图例去掉。相图很矮（≤520px）时示意图整块隐藏——它是装饰。

**更重要的改法在验收侧**：新增 `tools/verify-sizes.cjs` —— 在**十个窗口尺寸**下各跑一遍浏览器自检
（1400×900 → 1024×460、900×520），逐个尺寸报告通过/失败。理由是这类缺陷与尺寸强相关：
**单尺寸绿不等于各尺寸绿**，而人系统两次报的都是同一个现象、发生在两个不同的尺寸上。
加它之后立刻抓到两处我自己写歪的判据（"浮层占宽度 34%"在窄窗口下必然误报；
"只画路径时颜色数减少"在窄画布上因颜色饱和而失去分辨力），两处都改成了有明确物理含义的判据。

**这十三条共同的教训**：验收必须走与使用者相同的路径、并且**跑在会触发问题的条件下**
（窗口尺寸、前后台、数据规模）。"全绿"本身不是证据——只有"改坏了会红、改了能绿"才是。
故障十三另有一条：**"看得见"这类要求必须成批验收**——布局与窗口尺寸强相关，
只在一个尺寸下通过，等于没有验收；把尺寸做成参数（`tools/verify-sizes.cjs`，十个尺寸逐个跑）才算数。
故障七、八、九还说明**"看不见"与"点不动"本身就是一类缺陷**：它们不报错、不崩，断言也可能全绿，
只有真的把画面渲染出来看一眼、或者**去点一下每一个按钮**才会暴露。
故障九另有一层：**界面元素也要被断言覆盖**——只断言"数据流对"，
漏掉"按钮插进来的到底是什么"这种界面契约，一个坏按钮就能一直躺在界面上。
故障十则是**"参数联动"这一类缺陷的典型形态**：中间量在编译期算了一次就被冻住，
症状只表现为"调了没反应"，而且它恰好被"给每个参数都装滑杆"这个设计掩盖了——
所以**派生量不该有滑杆**，它只能是读数；凡"输入"与"中间量"混在一张表里，
这类 bug 就会一直藏下去。故障十一提醒：**默认视图要给人看他此刻要的东西**——
我花力气做的概率云是上一轮的需求，但这一轮他要先看见路径，那么默认就该是路径。

1. **视觉外观只对二维视图抓过屏**。一维相线与三维投影这两条路径，本轮浏览器能力在中途关闭过
   （Chromium 新进程需要 mojo 命名管道，被沙箱拒绝：`platform_channel Check failed 拒绝访问 0x5`，
   退出码 21）。因此它们由 `verify-render.mjs` 的 50 项结构断言与 `verify-app.mjs` 的交互断言覆盖
   （125 支箭头、投影可逆、轨迹段数、一维缩放平移的数值），但**没有截图级证据**。
2. 数值上：Euler/Heun/RK4 可选，够用；相流的边界形变用 96 个顶点近似，
   强拉伸时（如 Lorenz 长时间演化）边界多边形会自交，此时"面积比"读数不再有物理意义。
3. 三维视图里"区域"退化为以当前状态为中心的一簇状态（球状点阵）——三维中用鼠标框选一个体积
   需要另一套交互，本轮没有做，界面里如实标注为"撒一簇"。

## 六、为什么这样实现（几个被验证逼出来的选择）

- **不用 `new Function`**：表达式来自用户输入，闭包编译既能给出行列级错误定位，产物也可审计。
- **`t` 是保留名**：状态变量叫 `t` 时，方程里 `t` 会静默指向时间而不是状态 —— 图能画出来，
  意思却被换掉了。这类"安静的错误"必须在编译期拒绝。
- **状态读数用三次 Hermite 插值**（端点导数由向量场给出）：线性插值在 dt=0.1 时误差 ~1e-3，
  动画看起来就是"一跳一跳"的；Hermite 把误差降两个数量级，测试里两条插值路径并列断言。
- **播放推进与 rAF 解耦**：页面若在后台标签页打开，浏览器会把 rAF 完全停掉、
  把计时器降到分钟级。播放逻辑做成纯函数 `stepPlayback(frames)`，自检走同步路径，
  验收才不会因为"窗口没在前台"而莫名其妙地失败（本轮踩过）。
- **点阵按整格排布**：格心居中、留出半格边距，每支箭头完整落在绘图区内，不靠裁剪切半支。
- **三维相机注视视窗中心**：Lorenz 的 z ∈ [0,55]，相机若盯着原点，整个吸引子会被投到画布外。
- **角度轴用 π 的倍数当刻度步长**：否则刻度会落在 0.7854 这种数上，而不是 -3π/2、π/2。
- **一个循环只留一个帧函数**：重绘与推进必须在同一条链上。链条一交接（把 rAF 接力棒从渲染函数
  交给推进函数），重绘就静默掉队了 —— 这正是"什么都不动"的根因。
- **时间位置属于使用者，不属于实现**：视图操作不碰时间游标；重算类操作把时刻搬过去而不是清零。
  只有"初始状态真的换了"才回到 t=0（那确实是另一条轨迹的起点）。
  这条不只是体验问题：它决定了断言能怎么写 —— 修复前时间会**回退**，修复后只会**向前**，
  因此"时间没有回退"本身就是一条可判定的不变量。
- **同一套交互入口服务多种视图模式时，坐标换算必须按模式分派**：一维把二维的换算借来用，
  后果不是画错而是**抛异常**；而事件处理器里的异常是静默失效，表现为"点了没反应"。
- **canvas 放进 flex 布局必须显式 `min-height: 0`**：它的自动最小尺寸取自 `height` 属性，
  而那个值常常正是上一帧写进去的可用空间 —— 于是它自己把自己锁死，拒绝收缩，把兄弟元素挤出窗口。
  配套的断言语义是"**它在不在窗口里**"（`getBoundingClientRect().bottom` vs `window.innerHeight`），
  而不是"它有没有被渲染"。
- **三维平移用屏幕像素偏移、不改注视点**：注视点由"视窗中心"自动维护，若平移也去改注视点，
  两者会互相打架（渲染时把平移覆盖掉）。
- **命令行抓屏必须用绝对路径**：`Bitmap.Save` 收相对路径时，落点取决于进程当前目录，
  本轮就出现过"脚本说 saved，文件其实不存在"。
- **改最大化窗口要先 `ShowWindow(SW_RESTORE)` 再 `MoveWindow`**：直接 MoveWindow 只改还原尺寸，
  窗口仍旧最大化 —— 本轮"把窗口改小以暴露布局缺陷"差点因此白测一轮。
